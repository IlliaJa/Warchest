## 2. What was measured

### 2.1 Teacher strength is machine-specific (R.10.13)

The recorded 0.787 was the laptop. On desktop-legion the *same* configuration measures
**0.567**, because 1.0 s buys 118 node expansions there against ~220 on the laptop (~8.5 ms vs
~4 ms per node; the four search configurations all measure 205–226 on the laptop, so the config
costs no expansions — the box does).

Consequence: **every ExIt loop run in this project's history ran on desktop-legion**, i.e.
distilled a teacher with a 0.07 ± 0.06 edge over its own student while the docs reasoned about
0.74–0.79 measured elsewhere. That explains "parity" more simply than any channel mechanism.

### 2.2 The exploration-plane bug (R.10.14) — the largest single find

`exploration_map_dict` (per-player per-cell visit counts) lives on `WarChestEnv`, not in
`GameState`, so `set_state` could not restore it and `_apply` incremented the *sim* env's copy
for every simulated line. **Board plane 5 is that map**, so every position a search bot
evaluated through `_sim_env` reached the nets as an accumulating count belonging to no position.

| effect | measurement |
|---|---|
| sim-env plane 5 vs the real one, policy top-1 change | **8.3 %** (mean TV 0.123, 145 states) |
| plane 5 zeroed | 13.8 % |
| for scale: the entire value of a 1.0 s search over its own prior | 13.1 % (R.10 M3) |
| teacher strength, four arms, before → after the fix | mean **+0.079** |
| `lookahead_critic` strength, same policy | **+0.16** (policy 0.71 in-run → **0.55 ± 0.05** at k=100) |

Fixed in the shared base (`LookaheadBot._sync_exploration_map`), so `PuctBot`,
`PolicyCriticBot` and `LookaheadCriticBot` are all covered. `PolicyThetaBot` encodes the live
env and never had the bug — which is consistent with it being the one policy-guided bot this
project measured as strong.

**Read every pre-2026-08-20 search number with this in mind.** `wr_lookahead`'s recorded
0.04 → 0.95 trajectory, `wr_vs_puct_train`, R.0.1's scaling read, R.8.1's behaviour split and
every gauntlet standing that includes a search bot were all measured against a handicapped
search.

### 2.3 Teacher configuration, decomposed (n=60, shared seeds, 1.0 s, desktop-legion)

| arm | pre-fix | post-fix |
|---|---|---|
| `cheat d1 k0` (the historical default) | 0.567 ± 0.064 | 0.717 ± 0.058 |
| `blind d1 k0` | 0.617 | 0.650 |
| `blind d3 k0` (PIMC voting) | 0.600 | 0.700 |
| **`blind d1 k2`** (forced playouts) | 0.700 | **0.733 ± 0.057** |
| `blind d3 k2` (both) | 0.550 | — |

Readings: blindness costs ~0, so R.10.4's label-noise fix is free; **forced playouts are the
one change that raises strength** (+0.13); PIMC voting is *free alone but harmful combined* —
at 118 expansions a 0.1-weight hedge gets ~12 nodes, forced playouts spend all 12 on quotas,
and both its vote and its pruned target become noise. Defaults now: `n_determinizations 1`,
`forced_playouts_k 2.0`, blind.

### 2.4 The imitation track, closed with five negatives

Teacher at 0.733, labels clean, plane fixed. Divergence between search and prior is only
**5.6 %** of moves (agreement 0.944) — the teacher wins by ~2.3 corrections per game.

| what was distilled | WR vs base | k |
|---|---|---|
| loop round, plane-corrupted, visits | 0.410 (REJECTED) | 100 |
| loop round, plane-fixed, visits | 0.480 (REJECTED) | 100 |
| loop round, plane-fixed, `--disagree-weight 20` | **0.520 (PROMOTED)** | 100 |
| offline: all 15502 samples | 0.500 | 200 |
| offline: the 867 disagreeing samples only | 0.520–0.530 | 200 |
| offline: `disagree_weight 20` | 0.565 → **0.503** on re-measure | 200 → 300 |
| offline: two rounds concatenated (2× disagreement) | 0.487 | 300 |
| offline: `completed_q` σ = 0.5 / 1 / 2 / 4 | 0.480 / **0.512** / 0.500 / 0.490 | 400 |
| offline: `visits` control in the same sweep | 0.460 | 400 |

Two things this establishes. **R.10.10 is inverted**: it measured disagree-only as the *harmful*
subset (0.28–0.29) and concluded CE imitation has a ceiling — but both of that measurement's
defects (cheating teacher, corrupted plane) sat *precisely* on the disagreeing subset, since
where search and prior agree the label is the policy's own argmax and no corruption can change
it. With clean labels the same subset is the only useful one. And **the ceiling claim survives
anyway, for a different reason**: nothing in the family gets past ~0.51. The post-distill
agreement of the completed-Q arms (0.96–0.997) says why — at 118 expansions the Q gaps between
top root children are small next to the policy's own logit gaps, so a target that respects the
margin barely moves the policy, and one that ignores it moves the policy as often wrongly as
rightly.

**Do not re-open**: more CE target shapes, more weighting of the 5.6 %, more games at the same
divergence rate. Each is now a measured negative.

## 4. The live bet, and its cost

PPO's gradient consumes game outcomes, so an edge that is diffuse over many small per-move
margins arrives as a lost game — a signal a per-move label cannot carry. That is the whole
argument for sparring over imitation.

Costs on desktop-legion (~8.5 ms/node, 10 workers, 64 episodes/batch, ~42 opponent plies).
**The node cap does not end a search early in simple positions** — it runs the full cap every
move (measured: 41 nodes/ply at `max_simulations=40` whether the position had 5 or 21 legal
moves) — so cost is flat:

| `p_puct_live` × nodes | rollout wall / batch | 1500 batches |
|---|---|---|
| 0.5 × 100 (current default) | ~114 s | ~47 h |
| 0.25 × 100, or 0.5 × 50 | ~57 s | ~24 h |
| 0.5 × 30 | ~35 s | ~15 h |

Strength scales with nodes: 118 nodes = 0.733 vs the raw policy, ~30 nodes ≈ 0.55, ~12 nodes
(a 0.1 s budget) = 0.500. Prefer *fewer episodes against a strong opponent* over many against a
weak one — B8 measured that an opponent you beat contributes near-noise after per-opponent
advantage centring.

**Calibrated expectation for the next run** (asked for explicitly, so it is recorded): new
checkpoint ≥0.55 vs its own init checkpoint at k=200 — **50–60 %**; ≥0.60 — **~30 %**;
≥0.70 — **~10 %**. The base rate in this repo is poor (A1+A3 = +4 % i.e. noise; the last two
runs ≈ +31 Elo, 1.4 σ), and the policy starts entropy-collapsed (`ent_frac 0.17`,
`verb_ent 0.276` of 2.43), which the opponent change does not address.

## 5. Next steps, in order

1. **Run the sparring PPO, gated.** Do not commit 1500 batches: ~300 batches, then a gauntlet
   against the init checkpoint at k ≥ 200. The in-run eval is not trustworthy for this decision
   (R.8.2: it reported 0.35 for a checkpoint that measured 0.55 over 200 games).
2. **Exploration.** The warm-started policy begins collapsed; `verb_entropy_coeff_final` 0.01 →
   ~0.015 is R.9.6 item 6 and matters more, not less, against a stronger opponent. Not done —
   it would confound the sparring A/B if bundled, so decide deliberately.
3. **If sparring is flat**: R.10.5d (record the search's own root value as a critic target — it
   is computed and thrown away), full Gumbel with sequential halving at the root (R.3b; the
   completed-Q half is shipped), and B4 (distil a small net so search stops costing 8.5 ms a
   node, which is what makes every option here expensive).
4. **Re-baseline the search bots.** Every gauntlet standing involving `lookahead_critic`,
   `puct`, `policy_critic` predates the plane fix and understates them.

## 7. Method traps paid for in this session

* **One field is not a result.** `disagree_weight 20` read 0.565 ± 0.035 in a 5-agent field at
  k=200 (intransitivity 0.300) and 0.503 ± 0.029 against base alone at k=300. The project's own
  standing rule caught this one a few hours late; prefer 2-agent fields at k ≥ 300 for a
  decision.
* **Wall-clock budgets are not portable.** Quote node counts. Run `preflight` gate 3 on the box
  that will do the work, and never quote a teacher-strength number without the machine.
* **`SimpleNamespace` stubs hide attribute typos.** `self._wr_vs_lookahead` (the deque is
  `_wr_vs_lookahead_critic`) passed 21 tests and would have crashed the first eval of a real
  run. The user's `test_the_stub_reads_the_same_attributes_the_real_trainer_sets` compares
  `co_names` against what `__init__` assigns — copy that pattern for any stub-tested method.
* **Two implementations of one metric disagreeing is a lead.** Gen-time agreement 0.928 vs
  eval-time 0.756 on the same samples is what exposed the plane bug. This repo computes several
  quantities twice (`_obs_logits` vs `joint_log_probs_batch`, gauntlet WR vs in-run eval,
  evaluator constants vs reward constants); diffing them is cheap and has paid twice.
* **Operational:** any script that spawns workers needs `if __name__ == '__main__'`;
  `pkill -f <pattern>` kills your own ssh shell when the pattern sits in its argv, and orphans
  the spawn children, which then silently weaken every search opponent by eating cores. Check
  `ps -eo ppid,args | grep spawn_main` before trusting a timing or strength number.
